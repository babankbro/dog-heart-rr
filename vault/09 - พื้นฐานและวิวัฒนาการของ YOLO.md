# ความรู้พื้นฐานและวิวัฒนาการของ YOLO

## 1. ความรู้พื้นฐานเกี่ยวกับการตรวจจับวัตถุ

การตรวจจับวัตถุ (object detection) เป็นงานทางคอมพิวเตอร์วิทัศน์ที่ต้องตอบพร้อมกันสองประเด็น ได้แก่ ภาพมีวัตถุประเภทใด และวัตถุนั้นอยู่บริเวณใด ผลลัพธ์โดยทั่วไปประกอบด้วยกรอบสี่เหลี่ยม $(x,y,w,h)$ คะแนนความเชื่อมั่น และความน่าจะเป็นของคลาส จึงแตกต่างจากการจำแนกภาพซึ่งให้เพียงป้ายกำกับระดับภาพ

วิธีตรวจจับเชิงลึกแบ่งโดยสังเขปเป็น two-stage detector และ one-stage detector กลุ่มแรก เช่น R-CNN ตรวจหาบริเวณที่น่าสนใจก่อน แล้วจึงจำแนกและปรับกรอบในขั้นต่อมา จึงมักมีความแม่นยำสูงแต่มีขั้นตอนซับซ้อน ส่วน one-stage detector ทำนายกรอบและคลาสโดยตรงจาก feature map ในการส่งข้อมูลผ่านโครงข่ายครั้งเดียว ทำให้เหมาะกับงานที่ต้องการความเร็ว YOLO หรือ “You Only Look Once” เป็นแนวคิดสำคัญของกลุ่มหลัง

YOLO รุ่นแรกเสนอให้มองการตรวจจับเป็นปัญหา regression แบบรวมศูนย์ โครงข่ายรับภาพทั้งภาพ แบ่งพื้นที่เชิงแนวคิดเป็นกริด และทำนายกรอบ ความมั่นใจ และคลาสพร้อมกัน การเห็นบริบททั้งภาพช่วยลดการตรวจพบวัตถุบนพื้นหลังที่ไม่เหมาะสม และการคำนวณครั้งเดียวทำงานแบบเวลาจริงได้ อย่างไรก็ตาม รุ่นแรกมีข้อจำกัดด้านการระบุตำแหน่งและวัตถุขนาดเล็ก โดยเฉพาะเมื่อวัตถุหลายชิ้นอยู่ในบริเวณใกล้กัน [Redmon et al., 2016](https://arxiv.org/abs/1506.02640)

สถาปัตยกรรม YOLO สมัยใหม่อธิบายได้เป็น 3 ส่วน ส่วน **backbone** สกัดคุณลักษณะจากพิกเซลตั้งแต่ขอบและพื้นผิวไปจนถึงรูปร่างระดับสูง ส่วน **neck** ผสานคุณลักษณะหลายความละเอียดเพื่อให้ตรวจได้ทั้งวัตถุเล็กและใหญ่ และส่วน **detection head** แปลง feature map เป็นกรอบ คะแนนคลาส และคะแนนความเชื่อมั่น ผลจากหลายตำแหน่งอาจซ้อนกัน จึงใช้ non-maximum suppression (NMS) เก็บกรอบคะแนนสูงและตัดกรอบที่มี IoU ซ้ำกันเกินเกณฑ์

การฝึกต้องมีภาพและกรอบจริง แบบจำลองลด loss ที่สะท้อนความคลาดเคลื่อนของกรอบ การมีอยู่ของวัตถุ และคลาส การประเมินนิยมใช้ precision, recall และ mean Average Precision (mAP) โดย $mAP_{50}$ ใช้ IoU 0.50 ส่วน $mAP_{50:95}$ เฉลี่ยหลายเกณฑ์ตั้งแต่ 0.50–0.95 จึงเข้มงวดต่อความพอดีของกรอบมากกว่า ค่า confidence, IoU ของ NMS และขนาดภาพอนุมานเป็นพารามิเตอร์ที่มีผลต่อสมดุลระหว่างการพลาดวัตถุกับผลบวกลวง

## 2. วิวัฒนาการของตระกูล YOLO

**YOLOv1 (2016)** วางรากฐานการตรวจจับแบบ end-to-end จากภาพเต็มด้วยโครงข่ายเดียว จุดเด่นคือความเร็วและการใช้บริบทของภาพ จุดอ่อนคือ localization error และข้อจำกัดต่อวัตถุขนาดเล็กหรืออยู่รวมกันหนาแน่น

**YOLOv2 และ YOLO9000 (2017)** เพิ่ม batch normalization ใช้ anchor boxes ปรับขนาดอินพุตได้หลายระดับ และใช้ dimension clusters เพื่อกำหนด prior ของกรอบได้เหมาะกับข้อมูล การฝึกร่วมข้อมูล detection และ classification ทำให้ YOLO9000 รองรับหมวดวัตถุจำนวนมาก [Redmon and Farhadi, 2017](https://arxiv.org/abs/1612.08242)

**YOLOv3 (2018)** ใช้ Darknet-53 และทำนายสามสเกล จึงปรับปรุงการตรวจวัตถุหลายขนาด ใช้ logistic classifier แบบอิสระต่อคลาส และรักษาสมดุลความเร็วกับความแม่นยำได้ดี [Redmon and Farhadi, 2018](https://arxiv.org/abs/1804.02767)

**YOLOv4 (2020)** รวบรวมเทคนิคที่เพิ่มความแม่นยำโดยไม่ทำให้ต้นทุนอนุมานสูงเกินไป เช่น CSPDarknet, spatial pyramid pooling, PAN และกลยุทธ์เสริมข้อมูล งานรุ่นนี้ทำให้แนวคิด “bag of freebies” และ “bag of specials” ชัดเจนขึ้น กล่าวคือ แยกเทคนิคที่เพิ่มต้นทุนเฉพาะระหว่างฝึกออกจากโมดูลที่เพิ่มต้นทุนเล็กน้อยระหว่างอนุมาน [Bochkovskiy et al., 2020](https://arxiv.org/abs/2004.10934)

หลังจากนั้น ชื่อ YOLO มิได้มีสายพัฒนาเดียวอีกต่อไป **YOLOv5** พัฒนาโดย Ultralytics เน้นระบบฝึกและนำไปใช้งานที่สะดวกใน PyTorch ขณะที่ **YOLOX** นำแนวคิด anchor-free และ decoupled head มาใช้ และ **YOLOv7** ปรับการกำหนดสถาปัตยกรรมและเทคนิคฝึกเพื่อประสิทธิภาพเวลาจริง ดังนั้นหมายเลขรุ่นไม่ควรถูกตีความว่าเป็นลำดับบทความจากคณะผู้วิจัยเดียวกันทั้งหมด

**YOLOv8 (2023)** ของ Ultralytics ใช้ C2f ใน backbone/neck และหัวตรวจจับแบบ anchor-free แยกแขนง regression กับ classification รองรับ detection, segmentation, classification, pose และ oriented bounding boxes ภายใต้ API เดียว แนวทางนี้เป็นฐานทางวิศวกรรมโดยตรงของ YOLO11

## 3. YOLO11

Ultralytics เปิดตัว YOLO11 เมื่อวันที่ 10 กันยายน 2024 โดยใช้ชื่อทางการว่า “YOLO11” ไม่ใช่ “YOLOv11” ผู้พัฒนาไม่ได้เผยแพร่บทความวิจัยฉบับเป็นทางการเฉพาะรุ่น จึงควรอ้างอิงซอฟต์แวร์ เอกสาร และไฟล์กำหนดสถาปัตยกรรมของ Ultralytics โดยตรง ไม่ควรกล่าวอ้างรายละเอียดที่ไม่มีในเอกสารผู้พัฒนา [Ultralytics YOLO11](https://docs.ultralytics.com/models/yolo11/)

YOLO11 ยังคงโครงสร้าง backbone–neck–head และการทำนายหลายสเกล P3/8, P4/16 และ P5/32 กล่าวคือ feature map มี stride 8, 16 และ 32 พิกเซลต่อหนึ่งตำแหน่งตามลำดับ การใช้หลายสเกลทำให้ชั้นความละเอียดสูงเก็บรายละเอียดวัตถุเล็ก ขณะที่ชั้นลึกมี receptive field กว้างสำหรับวัตถุขนาดใหญ่

การเปลี่ยนแปลงสำคัญจาก YOLOv8 ได้แก่ (1) เปลี่ยนบล็อก C2f เป็น **C3k2** ซึ่งปรับหน่วย convolution ภายในตามขนาดโมเดล (2) เพิ่ม **C2PSA** หลัง SPPF เพื่อใช้กลไก attention เน้นคุณลักษณะที่สัมพันธ์กันในเชิงพื้นที่ และ (3) ทำแขนง classification ของ detection head ให้เบาลงด้วย depthwise-separable convolution ขณะที่ยังคงหัวตรวจจับแบบ anchor-free และ decoupled แยกการถดถอยกรอบจากการจำแนกคลาส [คำอธิบายสถาปัตยกรรมทางการ](https://docs.ultralytics.com/guides/yolo-architecture/) และ [ไฟล์ `yolo11.yaml`](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/cfg/models/11/yolo11.yaml)

หัว regression ใช้การแทนระยะขอบแบบการแจกแจงและ Distribution Focal Loss แนวทาง anchor-free ไม่ต้องกำหนดชุด anchor prior ล่วงหน้า ช่วยลดการพึ่งสมมติฐานรูปร่างวัตถุ แต่การฝึกยังต้องมีการกำหนด positive samples และ loss ที่เหมาะสม หลังทำนายยังใช้ NMS ในกระบวนการอนุมานมาตรฐาน

YOLO11 มีขนาด `n`, `s`, `m`, `l` และ `x` ผ่าน compound scaling ของความลึก ความกว้าง และจำนวนช่องสูงสุด รุ่นเล็กเหมาะกับทรัพยากรจำกัด ส่วนรุ่นใหญ่ให้ความจุสูงกว่าแต่ใช้หน่วยความจำและเวลาเพิ่มขึ้น เอกสารทางการรายงานว่า YOLO11m มี mAP บน COCO สูงกว่า YOLOv8m โดยใช้พารามิเตอร์น้อยลงประมาณร้อยละ 22 อย่างไรก็ดี ผลบน COCO ไม่สามารถใช้แทนผลบนภาพ EKG ได้ ต้องประเมินใหม่ด้วยข้อมูลเฉพาะงาน

YOLO11 รองรับ object detection, instance segmentation, image classification, pose estimation และ oriented bounding boxes รวมทั้งส่งออกสู่ ONNX, TensorRT และรูปแบบใช้งานอื่น ความยืดหยุ่นดังกล่าวเหมาะกับการสร้างระบบต้นแบบ แต่ความถูกต้องในงานชีวการแพทย์ขึ้นกับคุณภาพฉลาก ความสอดคล้องของ preprocessing และความเป็นตัวแทนของชุดข้อมูล มากกว่าความสามารถบน benchmark ทั่วไป

## 4. การประยุกต์ YOLO11 ในงานวิจัยนี้

ระบบใช้ YOLO ในสองบทบาท ขั้นแรกตรวจกรอบของรอบการเต้นจากภาพ EKG ที่ผ่าน preprocessing ขั้นที่สองตรวจ landmark หลายคลาสจากภาพครอปของแต่ละรอบ แล้วเลือกคลาส R การใช้ detector สำหรับ landmark ทำได้โดยสร้างกรอบขนาดเล็กรอบจุดกำกับและใช้จุดกึ่งกลางกรอบเป็นตำแหน่งทำนาย

แบบจำลองขั้นแรกมีเป้าหมายด้าน recall เพื่อไม่พลาดรอบการเต้น แต่กล่องที่เพิ่มขึ้นต้องผ่านการจัดแถว การคัดกรองขอบ และการตัดซ้ำ แบบจำลองขั้นที่สองมิได้ถูกเชื่อโดยอัตโนมัติ ตำแหน่งจะถูกเปรียบเทียบกับ R anchor จากหมึกและ row pitch หากไม่สอดคล้องและ confidence ไม่สูงพอ ระบบใช้ anchor แทน กลไกนี้ทำให้ YOLO เป็นองค์ประกอบหนึ่งของระบบวัด ไม่ใช่กล่องดำที่กำหนดผลสุดท้ายเพียงลำพัง

ข้อจำกัดสำคัญคือ domain shift แบบจำลองครอปและแบบจำลองจุดถูกฝึกด้วยภาพคนละการแทนข้อมูล การเปลี่ยนจาก blackhat เป็น tophat-gray หรือจาก ink เป็น gray อาจทำให้สถิติพิกเซลและรูปร่างเส้นต่างจากชุดฝึก แม้ภาพจะดูชัดสำหรับมนุษย์ ดังนั้น `weights`, preprocessing, `imgsz`, crop geometry และ class map ต้องถือเป็นสัญญาร่วมของแบบจำลอง และประเมินแบบ end-to-end ด้วย R-peak, RR และ BPM ไม่ใช้ mAP ของกล่องเพียงตัวเดียว
